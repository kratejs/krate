# 3D benchmark

Compares the same scene on three variants, in headless Chromium:

| Variant | Package | Path |
| --- | --- | --- |
| `filament` | `@krate/3d` (Google Filament, WebGL 2) | compiled by the scene3d pass |
| `three-compiled` | `@krate/three` (three.js) | compile-time optimizations on (default) |
| `three-runtime` | `@krate/three` | `<Canvas compile={false}>`, the plain r3f-style runtime path |

This is a manual tool. It is not part of CI and not wired into `packages/benchmark/src/run.mjs`.
It adds no dependencies: it uses `playwright` and the packages already installed in the workspace.

## Scene

Generated by `scene.mjs` (one page per variant and per mode, `static` and `animated`):

- 1000 boxes (40 x 25) with one shared material, from `GRID.map(...)` over a module-level constant array
- 4 differently colored static meshes (2 boxes, 2 spheres, own geometry and material each)
- 100 spheres in a ring. `animated`: position driven by a signal that a `requestAnimationFrame` loop advances by a fixed step per frame. `static`: the same positions, constant
- a ground plane, one directional light (intensity 2), one ambient light (0.5)
- 1280x720 canvas, same camera (position, target, fov 50), shadows off, antialiasing off, ACES tone mapping

`window.__freeze(t)` stops the animation at time `t`, which the screenshots use.
`@krate/3d` compiles a `.map()` only when every item prop is constant, so its animated ring is
written out as 100 generated `<mesh>` elements (a `.map()` there would fall back to the runtime
path with a KR8701 warning). `@krate/three` uses the `.map()` form, which it optimizes.

## Run

```sh
pnpm install && pnpm build            # once, at the repo root (runtime dist, packages)
cd packages/compiler && go build -o "$SCRATCH/krate" ./cmd/krate
cd ../benchmark/3d
node run.mjs run --work "$SCRATCH/work" --krate "$SCRATCH/krate" --shots "$SCRATCH/shots"
node run.mjs report                    # regenerates RESULTS.md from results.json + notes.md
```

Options: `--runs 3`, `--warmup 120`, `--frames 600`, `--variants a,b`, `--pages static,animated`,
`--skip-build`, `--gl-default` (Chromium's default GL flags instead of forced SwiftShader).
Run one browser at a time; the harness does. The work dir (apps, `node_modules` symlinks, browser
profiles) should live outside `/tmp` on machines where `/tmp` is RAM backed.

## What is measured

Each variant app is built with `krate build` (production, minified), served from a static server
(no compression, no cache) and driven with Playwright Chromium. A fresh browser per run.

1. **Payload**: the files the page actually fetches, raw, gzip -9 and brotli. Engine = `filament.js`,
   `filament.wasm`, the `.filamat` files fetched. App JS = page script plus the Krate runtime chunk;
   for three the engine is bundled into the page script, so an `empty` page (a `<Canvas>` with no
   children) is built too and its JS is reported as the baseline.
2. **Startup**: ms since navigation start (`performance.now()`) to the first engine frame (the engine's own
   frame hook: `scene.onFrame` for filament, `addAfterEffect` for three), to engine ready, and to the last
   engine asset response.
3. **Frame cost**: 600 frames after 120 warmup frames. Each rAF the probe calls `gl.finish()` (waits for the
   GPU to finish the previous frame) and records the time, so the rAF interval is the real frame cost
   and not how fast commands are queued. Reported: FPS, median and p95 interval, main-thread
   TaskDuration/ScriptDuration per frame (CDP `Performance.getMetrics`), and CPU time per frame of the
   renderer and GPU processes (`/proc/<pid>/stat`).
4. **Draw and GL calls per frame**: a separate instrumented run (all `WebGLRenderingContext` and
   `WebGL2RenderingContext` prototype functions are wrapped, identically for all variants), averaged over 60 frames.
5. **Memory**: JS heap before and after `HeapProfiler.collectGarbage`, Filament's wasm heap
   (`Filament.HEAPU8.buffer.byteLength`), and RSS/PSS per process type (renderer, GPU, browser, other), found through the
   browser process tree.
6. Screenshots of each page at `__freeze(0.5)`.

`results.json` has the raw per-run data and the medians. `RESULTS.md` is the report.
