# AGENTS.md

Guidance for AI agents and human contributors working in this Krate docs site.

__PROJECT_DISPLAY_NAME__ is a [Krate](https://github.com/kratejs/krate)
documentation site. Content is Markdown/MDX under `content/docs/`; each file
becomes a page and each directory becomes a sidebar section. It ships with a
sidebar, table of contents, breadcrumbs, prev/next navigation, light/dark theme,
and WASM-powered full-text search (docfind). It's built with the Krate `docs`
plugin.

## Commands

```bash
npm install      # install deps (@krate/core CLI + @krate/runtime + @krate/components)
npm run dev      # dev server with hot reload (native file watching, no polling)
npm run build    # production build into dist/
npm run serve    # build and serve the production output
```

## Project layout

```
krate.config.ts          # Krate config: entry, outDir (dist), pagesDir, plugins (docs, sitemap)
tsconfig.json            # targets ES2022, jsx preserve, @/* -> src/* alias
public/                  # styles (site.css, docs-styles.css), search script, favicon
content/docs/            # the documentation pages (Markdown/MDX)
src/
  pages/                 # index.tsx (home), _layout.tsx shell, 404.tsx
  components/
    docs-layout.tsx      # docs page shell (navbar, sidebar, toc) — imports from @/components/docs
    docs/                # GENERATED by the docs plugin (SidebarNav, TOCNav, Breadcrumbs, ...) — editable
```

- `content/docs/` files are auto-discovered; `order`/`title` frontmatter control
  sidebar position and page title.
- `@/` maps to `src/` (see `tsconfig.json` paths); use `@/components/...` for imports.
- Treat any file/dir whose name starts with `_` as internal/private; the watcher
  and compiler skip these.

## Writing docs

Add Markdown/MDX files under `content/docs/`. Frontmatter:

```md
---
title: Getting Started
order: 1
---

# Getting Started
```

- Directories create collapsible sidebar sections.
- Headings become the table of contents; GFM tables, task lists, admonitions,
  and code highlighting are enabled (see `markdown` config in
  `krate.config.ts`).
- `src/components/docs/` is regenerated by the `docs` plugin on build/dev; edits
  made there affect the docs UI but are overwritten on regeneration, so prefer
  configuring behavior in `krate.config.ts` (docs plugin options) and styling in
  `docs-styles.css` / `site.css`.

## Configuring the site

`krate.config.ts` is where the real site setup lives:

- `seo.baseUrl` / `seo.siteName` — production URL and site name.
- `plugins` — `sitemap(...)` and `docs(...)`: `contentDir`, `layout`
  (`src/components/docs-layout.tsx`), `search` (docfind, `maxResults`), `links`
  (social links, e.g. `lucide:github`).
- `devServer.port` — default 3000.

## Key runtime APIs

- Hit pages use the shared `SiteLayout` (`src/pages/_layout.tsx`); docs pages use
  `DocsLayout` (`src/components/docs-layout.tsx`).
- `Head`, `Icon`, `Link` are provided globally for head/icon/link content.
- This is NOT React — use `@krate/runtime` signals, plain `class=`, no React hooks.

## Gotchas

- `dist/` is build output — never edit; the dev watcher ignores it plus `.krate`,
  `node_modules`, `.git`, and `_`-prefixed internal files.
- Don't run `krate build`/`dev` from inside `dist/`.
- If you add/rename a docs page, the sidebar and search index rebuild
  automatically on `dev`/`build`.
