# 3D with Filament

`@krate/3d` renders 3D scenes with [Google Filament](https://google.github.io/filament/)
(WebGL 2, through the `filament` npm package's WebAssembly build) from
Three.js-style JSX. Because the Krate compiler sees the whole scene tree at build
time, it does the work a runtime reconciler such as react-three-fiber does on
every page load: it flattens static transforms into world matrices, batches
identical meshes into instances, converts colors and light units, and turns
reactive props into direct typed-array writes. Nothing large is embedded in the
`krate` binary: the pre-compiled materials, the `matc` shader compiler and the
Filament WebAssembly all stay in packages or downloads.

```sh
pnpm add @krate/3d filament
```

```tsx
import { createSignal } from "@krate/runtime";
import { Canvas, OrbitControls } from "@krate/3d";

export default function Page() {
  const [rotY, setRotY] = createSignal(0);
  return (
    <div style={{ width: "100%", height: "400px" }}>
      <Canvas shadows camera={{ position: [0, 2, 6] }}>
        <group position={[0, 1, 0]}>
          <mesh position={[2, 0, 0]}>
            <boxGeometry />
            <meshStandardMaterial color="orange" roughness={0.4} />
          </mesh>
          <mesh rotation={[0, rotY(), 0]} castShadow onClick={() => setRotY(rotY() + 0.5)}>
            <sphereGeometry args={[1, 32, 16]} />
            <meshStandardMaterial color="#4488ff" />
          </mesh>
        </group>
        <directionalLight intensity={1.5} position={[5, 5, 5]} castShadow />
        <ambientLight intensity={0.2} />
        <OrbitControls />
      </Canvas>
    </div>
  );
}
```

The engine is not bundled into your page. The build copies `filament.js` and
`filament.wasm` from your app's `filament` package into
`dist/assets/3d/filament-<version>/`, copies the packaged materials into
`dist/assets/3d/materials-<version>/` (both honour your base path), and the page
loads the engine with a plain script tag when the scene starts. If the `filament`
package is missing, or its version differs from the one the packaged materials
were built for (1.53.4), the build prints the warning
[KR8702](/docs/reference/diagnostics/#kr8702) with the hint to install it, and
the scene cannot start in the browser.

The canvas fills its parent, so give the parent a size. Only the canvas element
is server-rendered; the scene starts in the browser once Filament has loaded.

## Elements

| Element | Props |
| --- | --- |
| `<Canvas>` | `shadows`, `bloom`, `ssao`, `antialias` (`"taa"`, `"fxaa"`, `"msaa"`, `"none"`), `toneMapping` (`"aces"`, `"filmic"`, `"agx"`, `"linear"`), `camera` (`position`, `target`, `fov`, `near`, `far`), `exposure`, `class`, `style`, `id`, `onCreated`, `filament`, `materialBase`, `pixelRatio` |
| `<group>` | `position`, `rotation` (Euler XYZ radians), `scale` |
| `<mesh>` | `position`, `rotation`, `scale`, `castShadow`, `receiveShadow`, `onClick`, `onPointerOver`, `onPointerOut`, `onPointerMove`, `onPointerDown`, `onPointerUp`; one geometry and one material child |
| `<boxGeometry>`, `<sphereGeometry>`, `<planeGeometry>` | `args` as in Three.js |
| `<meshStandardMaterial>`, `<meshPhysicalMaterial>`, `<meshBasicMaterial>` | `color`, `roughness`, `metalness`, `emissive`, `emissiveIntensity`, `opacity`, `transparent`, texture maps (`map`, `normalMap`, `aoMap`, `roughnessMap`, `metalnessMap`, `emissiveMap`), and for physical `clearcoat`, `clearcoatRoughness`, `sheenColor`, `sheenRoughness`, `transmission`, `ior` |
| `<shaderMaterial>` | custom GLSL, see [custom shaders](#custom-shaders) |
| `<directionalLight>`, `<pointLight>`, `<spotLight>`, `<ambientLight>` | `color`, `intensity`, `position`, `castShadow`; point and spot also `distance`; spot also `target`, `angle`, `penumbra` |
| `<OrbitControls>`, `<Environment>` | orbit, zoom and pan; image-based lighting from a Filament KTX1 cubemap (`files` or a registered `preset`) |

`useFrame` and `useGLTF` are exported for per-frame callbacks and glTF models.
Colors are CSS color names, `#rgb`, `#rrggbb`, `rgb()` or `0xRRGGBB` numbers,
converted from sRGB to linear for you. Filament has no `setShadowingEnabled`, so
`shadows` on the `<Canvas>` gates `castShadow` and `receiveShadow`: they do
nothing without it.

## What the compiler does

For every `<Canvas>` imported from `@krate/3d` whose scene it can analyse, the
compiler replaces the JSX with one function of direct engine calls. No `<mesh>`
reaches the browser.

- **Static flattening.** A prop that folds to a constant (a literal, arithmetic
  such as `Math.PI / 2`, or a module-level `const`) is static. Static `group`
  and `mesh` transforms are composed into one world matrix at build time and
  emitted as `scene.staticMesh(...)`.
- **Slots for reactive props.** A mesh with a reactive `position`, `rotation` or
  `scale` (a signal read or any other non-constant expression) gets a transform
  slot: `scene.dynamicMesh(slot, ...)` with its static ancestors folded into a
  parent matrix, and one effect per reactive prop that writes straight into a
  typed array. Once per frame the runtime composes only the changed slots and
  updates the transform manager in one transaction.
- **Deduplication.** Geometries and materials with identical static arguments
  share one handle.
- **Auto-instancing.** Two or more meshes with the same geometry, material and
  shadow flags and fully static transforms, written out or produced by mapping a
  module-level constant array, become one `scene.instanced(...)` call with a
  `Float32Array` of matrices. Meshes with event handlers stay individual. This is
  not GPU instancing: Filament's JavaScript API (1.53.4) has no instance buffer,
  so the runtime creates one renderable per copy that shares the geometry and
  material, which still saves the uploads and the material setup.
- **Materials.** Static props are folded into the material's creation call with
  colors already linear. A reactive prop becomes an effect that updates the
  material instance. `transparent`, an opacity below 1 or a reactive opacity
  selects the blended material.
- **Lights.** Three.js-scale intensities are converted to Filament units at
  build time; a reactive intensity is converted in the browser with the same
  constants. A directional light's direction comes from its position toward the
  origin (or its `target`).

Lists compile when they map a constant array:

```tsx
const GRID = [[-2, 0], [-1, 0], [0, 0], [1, 0]];

<Canvas>
  {GRID.map(([x, z]) => (
    <mesh position={[x, 0, z]} scale={0.4}>
      <boxGeometry />
      <meshStandardMaterial color="gold" />
    </mesh>
  ))}
</Canvas>
```

The four meshes become one instanced call. A list over a signal is not known at
build time and sends the scene to the fallback below.

## Units and exposure

The default camera is a neutral physical exposure of f/16, 1/125 s and ISO 100
(EV100 of about 15), which puts direct sunlight near middle grey. Three.js-scale
light intensities are mapped to Filament units:

| Three.js | Filament | Mapping |
| --- | --- | --- |
| `directionalLight` | illuminance in lux | intensity x 110000 |
| `pointLight`, `spotLight` | luminous power in lumens | intensity x 4 x pi x 1000 |
| `ambientLight` | image-based light intensity (ignored while an `<Environment>` is active) | intensity x 30000 |

`exposure` on the `<Canvas>` adds exposure compensation in EV stops.

## Materials and shaders

`@krate/3d` has two material tiers.

**Tier 1, the default.** `meshStandardMaterial`, `meshPhysicalMaterial` and
`meshBasicMaterial` use pre-compiled `.filamat` files shipped in the npm package
(about 385 KB in total, with a blended variant of each). They are uber-materials:
texture maps and the other options are parameters, so there is no shader
compilation at build or run time.

**Tier 2, custom shaders only.** `<shaderMaterial>` needs a compiled material for
your GLSL, so the compiler generates a Filament `.mat` source, hashes it, and
compiles it with Filament's `matc`. The result is cached by hash, copied to
`dist/assets/3d/materials-<version>/<hash>.filamat` and referenced from the page script, so the
shader is fetched like any other static asset and an unchanged shader is never
compiled twice. The Filament version is part of the cache directory
(`.krate/cache/3d/<version>/`) and of the asset URL, because a `.filamat` only
works with the release that compiled it. `matc` is not embedded in `krate`: the first build that needs it
downloads the Filament 1.53.4 release for your platform into
`~/.krate/tools/filament/<version>/bin/matc` and reuses it afterwards. Projects
with no `<shaderMaterial>` never download anything.

| Variable | Effect |
| --- | --- |
| `KRATE_FILAMENT_MATC` | Path of a `matc` binary to use instead of the downloaded one. |
| `KRATE_OFFLINE=1` | Never download. A shader that needs `matc` then fails the build with a diagnostic pointing at `KRATE_FILAMENT_MATC`. |

A `matc` that is missing, or a shader that does not compile, is reported as a
build error with the file position of the `<shaderMaterial>` and a hint; it is
never a crash.

### Custom shaders

```tsx
const WAVE = `
  float w = 0.5 + 0.5 * sin(materialParams.t * 3.0);
  material.baseColor = vec4(materialParams.tint * w, 1.0);
`;

<mesh>
  <planeGeometry args={[2, 2]} />
  <shaderMaterial
    fragmentShader={WAVE}
    uniforms={{ tint: [1, 0.5, 0.2], t: { type: "float", value: time() } }}
  />
</mesh>
```

| Prop | Meaning |
| --- | --- |
| `fragmentShader` | Required. The statements of Filament's `void material(inout MaterialInputs material)` after `prepareMaterial(material)`. Set `material.baseColor` (and `roughness`, `metallic`, ... for a lit material). |
| `vertexShader` | Optional. The statements of `void materialVertex(inout MaterialVertexInputs material)`. |
| `uniforms` | Optional object. A constant is declared by its shape: a number is a `float`, `[x, y, z]` a `float3`, `[x, y, z, w]` a `float4`. `{ type: "float" \| "float3" \| "float4", value: expr }` takes a value that may be reactive and updates the material when it changes. Read them as `materialParams.<name>`. |
| `shadingModel` | `"unlit"` (default) or `"lit"`. |
| `transparent` | Alpha blending. Unlit shaders have their color premultiplied by alpha for you. |

The shader strings must be constants: a literal, a template literal without
expressions, or a module-level `const`. The material is built with a `uv0`
attribute available.

## When the compiler leaves a scene alone

The compiler leaves a `<Canvas>` untouched when it cannot fully analyse it. Then
the `@renderer` component from `@krate/3d` mounts the scene in the browser and
creates the same Filament objects at run time, without the flattening,
instancing and direct writes. The scene still renders. Build output names the
reason with the warning [KR8701](/docs/reference/diagnostics/#kr8701):

```
src/pages/index.tsx:18:7: [KR8701] <Canvas> is not compiled ahead of time: the component <Ball> may return scene nodes the compiler cannot see through
```

These cause it:

- a spread prop (`<mesh {...props}>`), an unknown `<Canvas>` prop, or a prop the
  element does not support;
- a component or an unknown element inside the `<Canvas>`, or a dynamic tag;
- a reactive `<group>` transform (the runtime composes meshes against a static
  parent matrix), so keep animated transforms on the meshes;
- a list over a signal or any list that is not a module-level constant array,
  and any non-constant value inside a mapped item;
- a conditional or other expression child, such as `{show() && <mesh />}`;
- reactive geometry `args`, spot light `angle` or `penumbra`, or a
  `<shaderMaterial>` whose shader is not a constant string.

The runtime path does not support `<shaderMaterial>`, so a scene that uses one
should stay compilable.
